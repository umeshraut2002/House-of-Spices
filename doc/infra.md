Here is a comprehensive, step-by-step implementation guide to deploy this highly available, secure **3-Tier AWS Architecture**.

---

## Phase 1: Networking & Foundation (VPC)

First, set up the isolated network boundary across two Availability Zones (`us-east-1a` and `us-east-1b`).

### Step 1: Create the VPC

1. Go to **AWS VPC Console** $\rightarrow$ Click **Create VPC**.
2. Select **VPC and more** (or create manually).
3. Set Name tag: `3tier-vpc`.
4. IPv4 CIDR block: `10.0.0.0/16`.

### Step 2: Create Subnets

Create 6 subnets across two AZs:

* **Public Subnets** (For ALB & NAT Gateways):
* `Public-Subnet-1a` (`10.0.1.0/24`) in `us-east-1a`
* `Public-Subnet-1b` (`10.0.2.0/24`) in `us-east-1b`


* **App Private Subnets** (For EC2 Backend Containers):
* `App-Private-Subnet-1a` (`10.0.3.0/24`) in `us-east-1a`
* `App-Private-Subnet-1b` (`10.0.4.0/24`) in `us-east-1b`


* **Data Private Subnets** (For MySQL RDS):
* `Data-Private-Subnet-1a` (`10.0.5.0/24`) in `us-east-1a`
* `Data-Private-Subnet-1b` (`10.0.6.0/24`) in `us-east-1b`



### Step 3: Internet Access & Route Tables

1. **Internet Gateway (IGW):** Create an IGW, attach it to `3tier-vpc`, and route `0.0.0.0/0` in the **Public Route Table** to this IGW.
2. **NAT Gateway:** Create a NAT Gateway in `Public-Subnet-1a` (allocating an Elastic IP).
3. **App Route Table:** Create a private route table, add a route for `0.0.0.0/0` targeting the NAT Gateway, and associate it with both **App Private Subnets**.

---

## Phase 2: Security Groups Setup

Define explicit inbound/outbound rules to enforce strict tier isolation:

| Security Group Name | Inbound Rules | Description |
| --- | --- | --- |
| `ALB-SG` | HTTP (80) & HTTPS (443) from `0.0.0.0/0` | Public access to Load Balancer |
| `App-Tier-SG` | Port 80/8080 (or your container port) from `ALB-SG` | Only accepts traffic from the ALB |
| `Data-Tier-SG` | MySQL Port (3306) from `App-Tier-SG` | Only accepts DB traffic from App instances |

---

## Phase 3: Data Tier (Multi-AZ MySQL RDS)

1. Go to **Amazon RDS Console** $\rightarrow$ **Subnet Groups** $\rightarrow$ Create Subnet Group using `Data-Private-Subnet-1a` and `1b`.
2. Go to **Databases** $\rightarrow$ **Create Database**:
* **Engine:** MySQL
* **Deployment Option:** **Multi-AZ DB Instance** (creates Primary in `us-east-1a` and Standby in `us-east-1b` with synchronous replication).
* **VPC:** Select `3tier-vpc`.
* **Subnet Group:** Select the Data Subnet Group created above.
* **Public Access:** **No**.
* **VPC Security Group:** Select `Data-Tier-SG`.


3. Save the DB Endpoint, Username, and Password for the application configuration.

---

## Phase 4: Frontend Presentation Tier (S3 & CloudFront)

1. **S3 Bucket:**
* Create an S3 bucket (e.g., `my-frontend-assets-3tier`).
* Keep **Block all public access** enabled.
* Upload your static frontend build files (HTML, CSS, JS, assets).


2. **CloudFront Distribution:**
* Create a distribution targeting your S3 bucket as the **Origin**.
* Configure **Origin Access Control (OAC)** so S3 restricts access exclusively to CloudFront.
* Update the S3 Bucket Policy using the policy generated by CloudFront.



---

## Phase 5: Application Tier (EC2, Container, & Auto Scaling)

### Step 1: Prepare Launch Template

1. Open **EC2 Console** $\rightarrow$ **Launch Templates** $\rightarrow$ **Create Launch Template**.
2. Select Amazon Linux 2023 AMI and instance type (e.g., `t3.micro`).
3. Set Security Group: `App-Tier-SG`.
4. In **User Data**, add a bootstrap script to install Docker/runtime, pull, and launch your backend container:
```bash
#!/bin/bash
yum update -y
yum install -y docker
systemctl start docker
systemctl enable docker
# Run your backend container, connecting to the RDS Endpoint
docker run -d -p 8080:8080 -e DB_HOST=<RDS_ENDPOINT> -e DB_USER=<USER> -e DB_PASS=<PASS> <YOUR_CONTAINER_IMAGE>

```



### Step 2: Application Load Balancer (ALB)

1. Go to **Load Balancers** $\rightarrow$ **Create Application Load Balancer**.
2. **Scheme:** Internet-facing.
3. **VPC:** `3tier-vpc`.
4. **Mappings:** Select `Public-Subnet-1a` and `Public-Subnet-1b`.
5. **Security Group:** `ALB-SG`.
6. Create a **Target Group** (HTTP port 8080) targeting Instance targets in `App-Private-Subnets`.

### Step 3: Auto Scaling Group (ASG)

1. Go to **Auto Scaling Groups** $\rightarrow$ **Create ASG**.
2. Select your Launch Template.
3. Choose `3tier-vpc` and select **App-Private-Subnet-1a** and **App-Private-Subnet-1b**.
4. Attach to the existing **ALB Target Group** created in Step 2.
5. Set Capacity: Desired = `2`, Min = `2`, Max = `4`.
6. Enable Target Tracking Scaling Policies (e.g., CPU utilization > 60%).

---

## Phase 6: DNS & Traffic Routing (Route 53)

1. Open **Amazon Route 53 Console** $\rightarrow$ **Hosted Zones**.
2. Select your domain name.
3. **Create Records:**
* **Frontend Record:** Create an `A` record with **Alias** pointing to your **CloudFront Distribution**.
* **API/Backend Record:** Create an `A` record (e.g., `api.yourdomain.com`) with **Alias** pointing to your **Application Load Balancer**.



---

## Verification & Testing Checklist

* [ ] **Connectivity Test:** Access your domain; verify static assets load via CloudFront.
* [ ] **API & DB Routing:** Execute an application action that triggers a DB write. Ensure traffic routes from `CloudFront/Client` $\rightarrow$ `ALB` $\rightarrow$ `EC2 Containers` $\rightarrow$ `RDS Primary`.
* [ ] **High Availability Test:** Simulate an instance or AZ failure to confirm the Auto Scaling Group and Multi-AZ RDS failover function seamlessly.
